# `ui-radio-button`

Consumer-facing documentation for `ui-radio-button` and `ui-radio-button-group`.

## Import

```ts
import { UIRadioButton, UIRadioButtonGroup } from '@bepower/ui-kit';
```

Both components are standalone Angular components.

## Basic usage

```html
<ui-radio-button-group
  ariaLabel="Charging method"
  name="charging-method"
  [(value)]="selectedMethod"
>
  <ui-radio-button value="fast" label="Fast charge"></ui-radio-button>
  <ui-radio-button
    value="standard"
    label="Standard charge"
    description="Use the normally available power"
  ></ui-radio-button>
</ui-radio-button-group>
```

`ui-radio-button` is not a card: it has no surface, border, padding or rounded container. It wraps
Ionic's `ion-radio`, while `ui-radio-button-group` wraps `ion-radio-group` for single selection and
native keyboard behavior.

## `ui-radio-button` inputs

### `value`

Required string value of the option.

Type: `string`.

### `label`

Required accessible name and visible label. It is rendered with the simple `16/24` paragraph style
when no description is provided, or as the `16/24` semibold title when a description is present.

Type: `string`.

### `description`

Optional descriptive text. When present, the radio aligns to the first line of the text column and
the description is referenced through `aria-describedby`.

Type: `string | undefined`. Default: `undefined`.

### `disabled`

Disables the option. Group-level and Angular Forms disabled states are merged.

Type: `boolean`. Default: `false`.

### `invalid`

Applies the error presentation to the option. It composes with focus and selection.

Type: `boolean`. Default: `false`.

### `errorText`

Optional error message associated with the radio. It is announced with `role="alert"` and does not
replace the label or description.

Type: `string | undefined`. Default: `undefined`.

## `ui-radio-button-group` inputs

### `ariaLabel`

Required accessible name for the group. It is rendered as a visually hidden `legend` and forwarded
to the Ionic group.

Type: `string`.

### `name`

Name forwarded to `ion-radio-group`. A unique name is generated by default.

Type: `string`.

### `disabled`, `invalid`, `errorText`

Group-level states. They propagate to projected radio buttons and merge with local states.

## Model and Angular Forms

`value` is a two-way bindable selected string value. `null` means no option is selected.

```html
<ui-radio-button-group ariaLabel="Charging method" [(value)]="selectedMethod">
  <!-- radio buttons -->
</ui-radio-button-group>
```

`UIRadioButtonGroup` implements `ControlValueAccessor`:

```html
<ui-radio-button-group ariaLabel="Charging method" formControlName="method">
  <!-- radio buttons -->
</ui-radio-button-group>
```

## Accessibility and interaction

- The group uses native Ionic radio semantics and one roving tab stop.
- Arrow keys move to the next or previous enabled option; Space selects the focused option.
- The entire row is the activation area.
- Disabled options are skipped and are not focusable.
- The focus ring uses `:focus-visible` and does not change layout.
- The group requires an accessible name through `ariaLabel`.
- Error state must not rely on color alone; use `errorText` when a user-facing message is needed.

## Layout and responsiveness

The group fills the available width. A simple radio has no fixed container width. A button with a
description grows naturally with wrapped text; the radio stays aligned to the first line.

## Encapsulation note

The components intentionally use `ViewEncapsulation.Emulated`: Ionic discovers radios with
`ion-radio-group.querySelectorAll('ion-radio')` and each radio resolves its group with
`closest('ion-radio-group')`. Separate Shadow DOM boundaries would break Ionic's group behavior.
