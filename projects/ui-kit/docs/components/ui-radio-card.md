# `ui-radio-card`

Consumer-facing documentation for the `ui-radio-card` and `ui-radio-card-group` components.

## Import

Both components are standalone Angular components.

```ts
import { UIRadioCard, UIRadioCardGroup } from '@bepower/ui-kit';
```

## Basic usage

```html
<ui-radio-card-group ariaLabel="Charging method" name="charging-method" [(value)]="selectedMethod">
  <ui-radio-card
    value="fast"
    title="Fast charge"
    description="Finish charging sooner"
  ></ui-radio-card>
  <ui-radio-card
    value="standard"
    title="Standard charge"
    description="Use the normally available power"
  ></ui-radio-card>
</ui-radio-card-group>
```

`ui-radio-card-group` owns the real Ionic `ion-radio-group`; each `ui-radio-card` owns an
`ion-radio`. This preserves Ionic's single-selection, arrow-key navigation, Space activation,
disabled-option skipping and roving tab index behavior. Clicking anywhere on a card selects its
radio.

## `ui-radio-card` inputs

### `value`

Required string value submitted by the option.

Type: `string`.

### `title`

Required visible title and accessible name of the radio option. Blank values are rejected.

Type: `string`.

### `description`

Required visible description. It is linked to the Ionic radio through `aria-describedby` rather
than being duplicated into its accessible name. Blank values are rejected.

Type: `string`.

### `disabled`

Disables only this option. Group-level disabled state is merged with this value.

Type: `boolean`. Default: `false`.

### `invalid`

Applies the error presentation to this option. Group-level invalid state is merged with this
value. Error and focus are independent: focusing an invalid card keeps the error state and adds
the focus ring.

Type: `boolean`. Default: `false`.

### `errorText`

Optional error message added after the description. It does not replace the option content and is
included in the radio's descriptive association.

Type: `string | undefined`. Default: `undefined`.

## `ui-radio-card-group` inputs

### `ariaLabel`

Required accessible name for the radio group. It is rendered as a visually hidden `legend` and
forwarded to `ion-radio-group`. Blank values are rejected.

Type: `string`.

### `name`

Group name forwarded to Ionic. A unique name is generated by default. Blank values are rejected.

Type: `string`.

### `disabled`

Disables every projected card and merges with the disabled state supplied by Angular Forms.

Type: `boolean`. Default: `false`.

### `invalid`

Applies error presentation to every projected card and marks the fieldset invalid.

Type: `boolean`. Default: `false`.

### `errorText`

Optional group-level error message. When present it also puts the group into the invalid state,
associates the message with the fieldset and renders it as an alert.

Type: `string | undefined`. Default: `undefined`.

## Model and Angular Forms

### `value`

Two-way bindable selected string value. `null` means no option is selected.

```html
<ui-radio-card-group ariaLabel="Charging method" [(value)]="selectedMethod">
  <!-- radio cards -->
</ui-radio-card-group>
```

`UIRadioCardGroup` implements `ControlValueAccessor`, so it also works with reactive and
template-driven forms:

```html
<ui-radio-card-group ariaLabel="Charging method" formControlName="chargingMethod">
  <!-- radio cards -->
</ui-radio-card-group>
```

The form's disabled state is propagated to all cards; blur marks the form control as touched.

## Layout and responsiveness

Both the group and every card fill the available inline size. The `327×98px` Figma frame is a
reference sample, not a fixed runtime size: at narrower widths title and description wrap, the card
grows vertically, and the radio remains centered. `FigmaReferenceWidth` in Storybook reproduces the
327px sample explicitly; the default and state stories are fluid, while `NarrowViewport` exercises
long content on the `iphone12mini` viewport.

## Accessibility and interaction

- The implementation uses Ionic's native radio semantics rather than simulating a radio with a
  generic button.
- The group is a single tab stop. Arrow keys move focus and selection to the next/previous enabled
  option with wrapping; Space selects the focused option.
- The title is the accessible name; the description and optional error message are descriptive
  text.
- The focus ring uses `:focus-visible`, so pointer interaction does not force keyboard focus
  presentation.
- Selected, invalid and focus states compose instead of replacing one another.
- Disabled cards remain at full opacity and communicate state through semantics and tokens, not
  color alone.
- Long text wraps and the card grows vertically while the radio stays centered.

## Encapsulation note

These two components intentionally use `ViewEncapsulation.Emulated`, unlike the kit's default
Shadow DOM pattern. Ionic 8 discovers its radios with `ion-radio-group.querySelectorAll('ion-radio')`
and each radio resolves its group with `closest('ion-radio-group')`. Separate Shadow DOM boundaries
would prevent that native group behavior. Emulated encapsulation keeps the styles scoped while the
real Ionic elements remain in the same DOM tree.
